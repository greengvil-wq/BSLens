# ADR-006-A. Ограниченный транспорт и инициализация MCP

Статус: библиотечный эксперимент, не пользовательский MCP-сервер.

## Граница этапа

`experimental-stdio` отдельно включает `mcp_transport::Session`. Она не включает
pipeline, не открывает репозиторий, не запускает Git, не читает исходники и не создаёт
службу или отдельный binary. `serve` получает явно переданные BufRead/Write, не обращаясь
к глобальным stdin/stdout/stderr. В выходной поток записываются только JSON-RPC frames.

Поддержаны initialize, notifications/initialized, ping и проверочный пустой tools/list.
Инструментов ядра, tools/call router, ресурсов, HTTP и смены конфигурации нет.
Production snapshot остаётся закрыт; Windows, БСП, ACL и антивирус не затрагиваются.

## Протокол

Проверена официальная schema MCP 2025-11-25:
[типы сообщений](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/2025-11-25/schema/2025-11-25/schema.ts),
[stdio](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports),
[lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).

JSONRPCErrorResponse имеет необязательный id, а RequestId допускает строку/число,
не null. Когда безопасно распознанного ID нет, ответ **не содержит** id, вместо
подстановки null. Поддерживаются строковые ID до 128 UTF-8 bytes и целые signed i64.
Дробные/экспоненциальные представления, -0, bool, null и выход за i64 отвергаются.
Строка "2" и число 2 различны. Распознанные ID корректных запросных envelopes
учитываются даже при ошибке параметров/метода и не могут повторяться в сессии.

Состояния: New → AwaitInitialized → Ready → Closed. Ping разрешён до готовности.
Initialize сообщает единственную поддерживаемую версию 2025-11-25 даже при иной
предложенной версии: клиент решает продолжить или отключиться. Только корректное
уведомление initialized после initialize открывает Ready; раннее/ошибочное ничего
не открывает. Объявлена лишь capability tools с пустым фиксированным списком.
Обязательные поля clientInfo и capabilities проверяются, дополнительные поля не
исполняются и не сохраняются. Повторная инициализация отвергается.

Разобранные сообщения без id с методом-строкой считаются уведомлениями и никогда
не получают ответа, в том числе при неизвестном методе/ошибочной оболочке. Неразбираемый
JSON или нарушенный framing не позволяют установить, было ли сообщение уведомлением:
в этих случаях возможна короткая ошибка без id. При исчерпании общего бюджета
сессия закрывается молча, без разбора следующего сообщения.

## Ограничения ресурсов

- До 65536 bytes на JSON body, без завершающего LF; CR перед LF входит в бюджет.
- До 1024 сообщений и 4 MiB совокупных bodies за сессию; уведомления и ошибки учитываются.
- До 32 уровней JSON-вложенности. Duplicate keys запрещены на любом уровне,
  включая совпадение ключей после декодирования Unicode escapes.
- ID-set ограничен числом сообщений. Длина method до 128 bytes.
- Превышение frame budget или EOF посреди строки закрывает сессию без дочитывания
  произвольно длинного входа. Разрешены обычные LF и CRLF; последняя строка требует LF.
- Ответ полностью проверяется по размеру до записи; превышение заменяется ограниченной
  ошибкой. Текущие ответы построены из фиксированных полей и ограниченного ID, без
  произвольного пользовательского содержимого. Это не обещание готового сериализатора
  будущих больших ответов инструментов.
- Ошибка Read/Write/flush закрывает Session и возвращает io::Error без паники/traceback.

Частотный лимит и фоновые таймеры здесь не нужны: действий инструментов нет, обработка
последовательная, общий объём и состояние ограничены. Блокирующее ожидание ввода и
backpressure выходного потока контролирует будущий владелец транспорта. Этот модуль
не заявляет hard wall-clock deadlines для произвольных Read/Write.

## Зависимость и следующий шаг

Для строгого duplicate-key Visitor нужна прямая optional `serde =1.0.229`.
Та же версия уже присутствовала транзитивно в Cargo.lock; новых пакетов/SDK нет.
`serde_json` остаётся парсером/сериализатором JSON, собственный JSON tokenizer не пишется.

После независимого ревью отдельная задача может добавить sealed startup с exact commit
и два read-only инструмента ядра. Нельзя объявлять этот этап готовым подключением MCP.

## Точная граница общего бюджета

После последнего разрешённого сообщения `serve` полностью записывает и сбрасывает
его ответ (если это запрос), затем закрывается с SessionLimit **до следующего чтения**.
Это относится и к ровно 1024 сообщениям, и к ровно 4 MiB bodies. Уже находящееся во
входном буфере следующее сообщение не потребляется. Прямой `handle_body` также сначала
проверяет исчерпание бюджета, поэтому oversized-вход после исчерпания не создаёт
дополнительной ошибки/ответа.

При непустом остатке reader ограничен меньшим из frame budget и оставшихся session
bytes. Допускается чтение одного дополнительного byte только для LF либо обнаружения
переполнения. Если следующая строка больше остатка, она не разбирается и не исполняется:
сессия закрывается молча, без дочитывания строки и без ответа на неё. Если строка ровно
заполняет остаток и завершается LF, она обрабатывается обычным образом, после чего
сессия закрывается. LF не входит в общий бюджет bodies.
