# ADR-005. Сквозной контекст Git и дерева структуры

Статус: экспериментальный интеграционный срез до модулей. Production-граница закрыта.

## Маршрут

`GitStructure::read` вызывает принятый Git-адаптер, получает проверенный Manifest,
передаёт выбранные bytes в XML-адаптер и строит принятую структурную проекцию.
`from_manifest` позволяет использовать уже проверенный тип без повторного чтения Git.
Самодельные manifest-значения через публичный API создать нельзя.

Ни один из трёх компонентов не переписан. Дополнительный слой только связывает
результаты и обрабатывает отказы. Методы, SQLite writer, MCP и production open
не добавлены. При отказе Git/XML/дерева частичный успешный результат не возвращается.

## Контекст и узлы

Каждая страница содержит точные commit/tree и количество выбранных/прочих файлов.
Выбор файлов наследуется от принятого Git-адаптера: точные суффиксы `.xml` и `.bsl`.
Остальные обычные файлы входят в проверенный Git manifest, но их содержимое не
интерпретируется XML-слоем. Нулевой счётчик прочих файлов не доказывает полноту
поддержки типов метаданных.

Идентификаторы узлов сквозного API обёрнуты в непрозрачный префикс с commit SHA.
Идентификатор из другого коммита вызывает ContextMismatch, даже когда XML-структура
совпадает и изменилось только тело модуля. Страницы неизменяемого коммита повторяемы.
Ни SHA коммита, ни эти идентификаторы не являются schema-v4 snapshot_id.

Внутренняя coverage проекции сохранена без изменений: её сообщение о непроверенном
происхождении относится к самостоятельной проекции, а не к внешнему Git-контексту.
Сквозной слой доказывает цепочку content-addressed Git-объектов и привязку страницы
к выбранному commit. Он не доказывает подпись автора, семантическую корректность 1С,
полный охват конфигурации или завершение проверки снимка.

## Ограничения страниц и платформы

Действуют лимиты принятых компонентов. После добавления commit-префиксов ещё раз
проверяется лимит текстовых полей узлов 16384 bytes. При превышении возвращается
TextBudget без усечения; можно запросить меньше детей. Это не лимит сериализованного
MCP/JSON ответа: такого транспорта в этом шаге нет. Контекст страницы ограничен
проверенными Git IDs и счётчиками, а не произвольным текстом пользователя.

Git backend остаётся Linux-only с отдельным доверенным executable resolver,
фиксированными подкомандами и временным private config. Рабочая копия не используется.
Все ограничения стабильности object store, времени, объёма и XML subset сохраняются.
