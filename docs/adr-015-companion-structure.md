# ADR-015: формы и макеты — структурный срез

Новая явная команда `build-companions`, профиль `linux-v5-companion1-xml221-r09`.
Основа — inline-кандидат 2e4a159. Старые команды, профили, DDL и их identity не
изменены. Версия контейнера SQLite остаётся 5; новый профиль имеет собственный
точный DDL: sources допускает payload, добавлены companions и companion_payloads.
Профиль, выбор источников и нормализованные бюджеты входят в snapshot_id; домен
канонических фактов `BSLens-v5/facts/companion1` включает обе новые таблицы.
Reader распознаёт точную схему. Старый reader явно отвергнет новый профиль.

## Подтверждённый контракт и границы

Согласованная обезличенная сверка pinned БСП подтверждает MDClasses scalar refs
Form/Template непосредственно в ChildObjects Catalog/Document/InformationRegister.
Дескриптор: `<родители>/<имя>/Forms/<форма>.xml` либо Templates/<макет>.xml,
MetaDataObject namespace MDClasses version 2.21, один прямой Form/Template,
валидный uuid, одно Properties/Name, совпадающее со ссылкой; ChildObjects нет.
Сохраняются настоящий путь дескриптора, непосредственный родитель объекта и
байтовый диапазон ссылки в исходном XML, включая поправку BOM. UUID уникален.
Дублированная ссылка/UUID, отсутствующий дескриптор, неверные имя/тип/namespace,
неизвестный ChildObjects или лишний неразрешённый XML — явный отказ.
Дополнительные семантические свойства не считаются разобранными.

Форма владеет только своим `Forms/<имя>/Ext/Form/Module.bsl`, если он существует.
Его отсутствие допустимо. Код проходит прежний ограниченный лексический анализ:
accepted/unparsed не смешиваются. Payload `Ext/Form.xml` не является дескриптором.
Макет может иметь `Ext/Template.xml`, `.bin` или `.txt`; отсутствие допустимо для
структуры, несколько известных payload считаются неоднозначностью и отвергаются.
Все прочие файлы внутри разрешённого companion-каталога сохраняются непрозрачно,
с role=additional. Их семантика не подтверждается, даже если расширение .bsl.
Дескриптор не заменяется payload ни при каких обстоятельствах.

Это не парсер содержимого форм/макетов. Payload всегда имеет kind=payload,
MCP source возвращает его Base64, даже если байты — валидный UTF-8. Источники и
Git blob OID/SHA сохраняются без преобразований. Inline/обычный XML и BSL могут
возвращаться UTF-8 либо Base64, без lossy. Единицы диапазона: байты, 0-based,
end-exclusive. Payload не становится модулем/методами.

## Навигация и проверка

После обычной ветки объекта MCP предлагает группу companions. `tree` с
`level=companions,parent_id=<id>` отдаёт одну ограниченную ветку: дочерние
дескрипторы, сохранённые payload и XML-доказательство ссылки для самого companion.
У дескриптора есть children на реальный объект формы/макета и source на XML.
`source` принимает возвращённые saved_path/start_byte/end_byte, читает только
диапазон incremental BLOB. Длинный диапазон следует разбить на части в пределах
объявленного byte_length/границ; полный JSON-RPC frame по-прежнему ≤65536 bytes.
Весь ответ отвергается при превышении бюджета, частичный payload не возвращается.
`contents=not_analyzed`, `coverage=structure_only`; payload_presence различает
present_unparsed, absent и not_applicable. Пустая ветка — не приёмка содержимого.

Offline verify повторно проверяет OID/SHA всех сохранённых источников, затем тем
же producer пересчитывает владельцев, ссылки, диапазоны, payload inventory и BSL.
Правдоподобный ошибочный owner с пересчитанными facts/file SHA проходит open,
но отвергается verify. Git provenance этим не подтверждается.
В одном процессе MCP reader открыт один раз, Git/повторный разбор BSL не нужны.

Бюджеты файлов/совокупного ввода/фактов/coverage/SQLite/времени — те же явные
аргументы, что у build-inline. Payload тоже расходует source/Git бюджеты.
Producer читает по одному телу; XML имеет собственные пределы. Время кооперативно,
не обещает прерывание каждого SQLite statement. На любом позднем отказе staging
builder удаляется, итоговый снимок не публикуется. Reader требует доверенный
артефакт, отдельный expected SHA, private staging; это не sandbox произвольного
SQLite. Поддержана только проверенная Linux x86_64, Rust 1.85.1.

## Воспроизведение

```
cargo +1.85.1 test --locked
cargo +1.85.1 test --locked --all-features
cargo +1.85.1 test --locked --all-features --test mcp_snapshot companions_cli
cargo +1.85.1 fmt --check
```

Последний тест запускает настоящий builder, удаляет только свой синтетический
Git, запускает offline verify с пустым PATH и реальный stdio MCP. Проверяет три
родителя, XML/bin/txt payload, отсутствие payload/кода, точный BSL BOM/CRLF/last no
LF, XML-диапазон ссылки, UTF-8 путь, порядок, budgets, parity общих старых фактов,
детерминизм, отказ без публикации и ошибочного владельца при корректных checksum.
Это автоматический тест, не ручной smoke и не фактический CI GitHub.

Команда сборки имеет те же 18 позиционных аргументов, что build-inline; заменить
имя команды на build-companions в [локальном руководстве](nucbox-companion-diagnostic.md).
Полная БСП здесь не выполнялась. Общие модули и остальные корневые типы пока
не поддержаны, это следующий отдельный срез. Все восемь разрезов и полноценная
приёмка Навигатора не завершены. До них запуск на БСП — диагностика, не acceptance.
