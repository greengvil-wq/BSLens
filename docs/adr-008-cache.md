# ADR-008-A. Ограниченный локальный кеш выбранных исходников

## Назначение

Feature `experimental-cache` добавляет явные `cache::build` и `cache::open`.
Обычный `GitStructure::read` не меняется. Кеш не создаёт `ValidatedSnapshot`,
не поддерживает Windows и не переносит результат на другой коммит.

Ключ: полный Git SHA и версия формата/логики `v1`. Изменения логики, влияющие
на идентичность кеша или интерпретацию его полей, требуют смены версии. Хранятся
только выбранные XML/BSL bytes, путь, mode и blob OID, commit/tree и счётчики.
Тела посторонних файлов не сохраняются. Производные узлы не десериализуются:
после открытия заново выполняются проверки XML-поднабора и построение Structure.
Методы анализируются при раскрытии модуля, как в обычном пути.

## Проверка при повторном открытии

1. Проверить owner-only каталог, обычный файл и ограничение размера до чтения.
2. Ограниченно разобрать бинарный формат, версию, ключ, длины и контрольную сумму.
3. Пересчитать Git blob OID каждого выбранного кешированного тела.
4. Через один ограниченный Git batch прочитать настоящий commit и tree objects,
   независимо пересчитать их хеши и получить полный список path/mode/OID.
5. Сопоставить tree, все выбранные записи и счётчики с реальным Git inventory.
6. Повторно проверить XML и построить структурное представление.

Оригинальные Git blob bodies при тёплом открытии не читаются. Настоящие commit/tree
должны оставаться доступными. Существующая проверка layout object-store сохраняется:
она перечисляет entries для запрета symlink/alternates/promisor, поэтому открытие
не является O(1). Тёплый путь не проверяет заново тела посторонних файлов, которые
не нужны возвращаемой структуре. Полная проверка всего манифеста остаётся холодным
`build`; кеш не объявляется полноценным снимком всей конфигурации.

## Доверие и ограничения

Это локальный Linux-кеш доверенного владельца: каталог mode 0700, файл 0600,
UID текущего процесса. Symlink-компоненты пути, файлы с несколькими hardlinks,
необычные типы файлов и небезопасные writable-родители отвергаются. Каждый
родитель должен принадлежать root или текущему UID; чужой 0755 также запрещён. Root-owned
sticky каталог, например `/tmp`, допустим как родитель. `O_NOFOLLOW` исключает
следование по последнему symlink, `O_NONBLOCK` исключает зависание на подставленном FIFO.

SHA256 всего payload выявляет случайную порчу, но не аутентифицирует файл против
злоумышленника того же UID. Привязка выбранных исходников всё равно подтверждается
Git tree и пересчитанными OID. Одновременная злонамеренная подмена каталогов владельцем
не входит в модель доверия; для такого сценария нужен отдельный защищённый backend.

Файл не больше 40 MiB; выбранные тела вместе с проверенными commit/tree bytes не больше 32 MiB, каждое не больше
8 MiB; не больше 4096 файлов всего. Заголовочные длины проверяются до выделения памяти.
Существующие лимиты Git tree/object-store и XML сохраняются. Граница размера кеша
включает метаданные и checksum, а не расширяет лимит полезных исходников.

## Публикация и ошибки

`build` получает полный проверенный манифест и рабочий результат ядра до публикации.
Запись идёт в новый private временный файл в том же каталоге: write, file sync,
atomic rename, directory sync. При ошибке временный файл удаляется; частичный payload
не читается как результат. Если directory sync неуспешен после rename, вызов возвращает
ошибку, хотя новый полный файл уже может существовать. Удаление/очистка старых версий
кеша автоматикой этого этапа не предусмотрены.

`open` не перезаписывает ничего и не маскирует порчу автоматическим rebuild.
Отсутствие кеша обозначается `Missing`; порча, неверная версия или идентичность дают
явный отказ. Вызывающий клиент отдельно выбирает построение/перестроение.

Новых Cargo-зависимостей нет. Получение effective UID использует Linux libc-вызов
`geteuid` без стороннего crate. БСП и Windows на этом этапе не проверялись.
