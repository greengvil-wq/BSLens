# ADR-001. Ядро Rust и закрытый production-контур

Статус: архитектура Rust согласована пользователем; R01 представляет только первый срез.

## Разделение обязанностей

- `lib.rs`: публичная граница полностью проверенного снимка и ошибки. Пока полная
  проверка не перенесена, получить `ValidatedSnapshot` невозможно.
- `validation.rs`: отдельный экспериментальный валидатор авторских BSL-снимков v4.
  Открывает SQLite только на чтение, устанавливает query_only/trusted_schema,
  читает в одной транзакции; затем закрывает соединение.
- `synthetic.rs`: чтение неизменяемых проверенных байтов в памяти. Отдельный тип
  `SyntheticSnapshot`, доступный исключительно при сборке `synthetic-dev`.
- `main.rs`: разбор CLI и маркированный JSON. Будущий MCP будет вызывать библиотеку
  напрямую, а не запускать Python или разбирать stdout CLI.

Дерево, семантические факты и MCP не включаем в этот шаг. Прежняя Python-реализация
использована только как внешний эталон для авторских данных, её код в проект не включён.
Новая Git-история не использует старый репозиторий как родителя.

## Что проверяется сейчас

Только профиль `synthetic-bsl-utf8-lines-v2`, schema_version/user_version 4; физическая
целостность SQLite; ожидаемый snapshot_id; формат точного Git SHA; SHA256 содержимого;
Git blob OID SHA1/SHA256; строгий UTF-8; побайтовое совпадение физических позиций;
непустые источники и корректные относительные адреса; отсортированный уникальный inventory,
его соответствие выбранным источникам; foreign_key_check; общий идентификатор manifest
с Python-совместимым ASCII JSON. Пути к снимку с символическими ссылками отвергаются.
Введён лимит файла 64 MiB, достаточный только для авторских тестов.

При запросе source повторно проверяется snapshot_id; диапазон включительно 1-based,
максимум 100 физических строк и 16384 байта, UTF-8 сохраняет BOM/CR/LF. Байтовые смещения
0-based, конец не включён. Пустой файл не имеет первой строки. metadata возвращается
копией, источники никогда не читаются из произвольного пути на диске.

## Что НЕ проверяется

Не перенесены повторное вычисление XML-адаптера и его scope/coverage, BSL facts и scope,
лексические границы и scope, полная проверка определения SQLite-схемы. Поэтому даже
успешный manifest hash не превращает экспериментальный снимок в production-данные.
Передаваемые metadata могут содержать ещё не проверенные утверждения этих подсистем.
CLI перечисляет непроверенные части рядом с явной маркировкой результата.
SHA и snapshot_id связывают внутренние данные, но не доказывают подпись автора или
наличие соответствующего коммита во внешнем Git. Одинаковый manifest не является
свидетельством полной семантической эквивалентности реализации Python.

## Дальнейшие небольшие задачи

1. R02: формальная модель и проверка схемы/лимитов, hostile-input и Windows path tests.
2. R03: XML-адаптер с проверкой всех поддержанных и исключённых структур, scope parity.
3. R04: BSL facts и независимая лексическая навигация; differential corpus и отказы.
4. R05: общий fail-closed validator, independent review и только затем production open.
5. R06: структурное дерево из проверенных фактов, ограниченные страницы и coverage.
6. R07: MCP-адаптер над библиотекой, проверки протокола и размеров, без Python runtime.

Порядок отдельных внутренних портов можно менять, но production-граница остаётся
закрыта до полной проверки. Windows, пользовательская база БСП, антивирус и ACL
в R01 не затрагиваются. Выкладка в GitHub отдельно от разработки и приёмки.
