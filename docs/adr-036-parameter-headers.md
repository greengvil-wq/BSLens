# ADR-036: однострочные заголовки с параметрами без defaults

Основа `e2e78fc53114edbf7032abd06c6d3e074e1335bc`. Явный CLI
`build-parameters`, профиль `linux-v5-parameters1-xml221-r09`, lexical_version
`r09-parameters-v1`. Старые guards R09 и context-only не изменены.
Новый профиль наследует ровно контекстные аннотации из [ADR-035](adr-035-context-annotations.md).

## Закрытый срез грамматики

```text
(Procedure | Процедура | Function | Функция) Identifier
    '(' [ Parameter { ',' Parameter } ] ')' [ Export | Экспорт ]
Parameter = [ Val | Знач ] Identifier
```

Вся декларация должна находиться на одной физической строке. Пробелы и табуляция
между токенами допустимы, комментарий `//` после заголовка допустим. Ключевые слова
и сравнение имён параметров используют прежнее lowercase; алфавит идентификатора —
ASCII буквы, русские буквы включая Ё/ё, `_`, затем также ASCII цифры. Дубли
параметров с учётом этого сравнения отвергаются. Применяется существующий явный
список запрещённых ключевых имён, дополнительно исключены имена структурных
ключевых слов, Val/Знач, Async/Асинх и Export/Экспорт. Это лексическая грамматика,
не проверка всех семантических правил компилятора.

В этом малом шаге **нет defaults**, включая обычные литералы. Любое `=` в списке
параметров, выражение, вызов, строка вместо имени, пустой элемент, хвостовая запятая,
повтор Export, дополнительная декларация или multiline дают отказ. Это осознанная
граница законченного среза: переданные 538 заголовков без defaults и пять случаев
с 1–4 параметрами служат основанием выбора, но не результатом облачного прогона.
191 случай с literal defaults и multiline остаются отдельной следующей задачей.
`#If` не добавлен.

Строки токенизируются целиком с прежним правилом удвоенных кавычек. Запятые,
скобки и `//` внутри строки не становятся токенами параметров/комментарием.
Строковый default всё равно отвергается; строки и комментарии тела не мешают
выделению границы метода. Незавершённые строки не принимаются.

## Ограничения и результат

Максимум 64 параметра, 8192 байта от первого до последнего токена заголовка,
200 токенов, 128 исходных байт на каждый токен заголовка. Эти величины проверяются
поверх прежних общих caps: 1 MiB исходника, 65536 строк и 100000 токенов.
Отступ и отброшенный хвост комментария не входят в 8192, но входят в общий предел
исходника. Переполнение — `Limit`, неподдержанная грамматика —
`UnsupportedHeader` либо более ранний конкретный лексический отказ.

Весь модуль при отказе остаётся `unparsed`, методы не публикуются даже после
допустимой декларации в начале файла. `unparsed` не означает отсутствие метода;
accepted без методов — отдельный статус. Источник доступен точно по диапазону.
Список параметров не становится семантическими фактами; извлекаются прежние
границы/имя/вид/Export метода. Не заявляется анализ тела или типов.

BOM/CRLF и конец без LF сохраняются. Method byte range начинается с ключевого
слова декларации; header range заканчивается последним токеном (до комментария).
Контекстная аннотация не включается в method range, оставаясь в источнике.
Физические строки, source_lines, поиск неоднозначных имён остаются прежними.

## Общий producer, identity и offline verify

Build и offline verify выбирают один `analyze_parameters_v1` по новому профилю.
Нормализованные build_parameters включают lexical_guard, grammar, четыре предела,
multiline=false/defaults=false. Они участвуют в snapshot_id; metadata lexical_version
проверяется reader. DDL меняет только discriminator; источники, owners,
XML diagnostics storage/count/digest, facts digest, все файловые/SQLite/time/wire
квоты наследуются без расширения. MCP сообщает новый guard и отсутствие
семантической проверки compiler_context.

Команда и 21 аргумент по [ADR-034](adr-034-root-sidecars.md): заменить имя build
на `build-parameters`. Verify и stdio MCP без Git остаются прежними, с explicit
BIN/diagnostics caps, trusted staging и expected SHA. Не удалять рабочий Git на NucBox.

```sh
cargo +1.85.1 test --locked --features experimental-snapshot-mcp parameter_ -- --nocapture
cargo +1.85.1 test --locked --all-features
cargo +1.85.1 test --locked --features experimental-router
cargo +1.85.1 test --locked
cargo +1.85.1 fmt --check
git diff --check
```

Синтетическая проверка: настоящие build → удаление собственного временного Git →
offline verify → stdio с пустым PATH. BOM/CRLF, контекстные аннотации, 1–4 параметра,
Val/Знач, Export, точные методы/исходники, ambiguity, честный unparsed, сохранённые
diagnostics, deterministic identity, отказ старого context-only guard, late facts
limit с пустым output и rollback. Подмена имени метода с пересчитанными digest
принимается формальным open, но отвергается повторным derive в offline verify.
Unit-векторы отдельно проверяют пределы 64/65, 128/129, размер заголовка, дубли,
строки/комментарии, malformed/multiline/defaults и границы pending-аннотации.

Реальная БСП не использовалась. Эффект на её accepted/method counts неизвестен до
отдельного локального прогона. Это не приёмка полной БСП; main/GitHub не изменяются.
