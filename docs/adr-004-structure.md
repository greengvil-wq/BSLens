# R04-A. Экспериментальное дерево структуры

Вход — только `Xml221Subset` принятого R02. Выход — read-only библиотечная
проекция: конфигурация → группы типов → объект → модуль. Модули конфигурации
находятся прямо под корнем. Группа неподтверждённых модулей отделена; владелец
не угадывается. Группы синтетические, не объекты метаданных.

Включение: feature `experimental-tree`, автоматически включает `experimental-xml`.
Никакого SQLite, Git, диска, MCP, тела BSL или запуска платформы в этом модуле нет.
Production gate остаётся закрытым. Неподдержанные XML-типы до построения дерева
отвергаются адаптером R02, не превращаются в пустую ветку.

## Навигация и границы

`page(None, offset, limit)` читает непосредственных детей корня; `page(Some(id), …)`
читает непосредственных детей узла. Лимит от 1 до 20; нулевой/больший лимит — ошибка.
Позиция за концом даёт пустую страницу без продолжения. У каждого ответа есть
`total`, `next_offset` и coverage, включая число непроверенных XML-записей и
модулей без владельца. Пустая ветка не доказывает отсутствие механизмов платформы.
У модуля пока нет детей: методы **не реализованы**, а не «не найдены».

Адрес и метка узла ограничены 1024 UTF-8 байтами. Сумма байтов строковых полей
узла и элементов страницы ограничена 16384; при превышении возвращается
`TextBudget`, без частичного результата и молчаливого обрезания. Можно запросить
меньший limit. Это лимит полей библиотечного ответа, не размер JSON/MCP-конверта.
Транспортный лимит потребуется отдельно при реализации MCP.

Объекты и модули упорядочены по точным адресам, группы по имени типа; корневые
модули идут перед группами, unassigned — последним. Порядок повторяемый.

## Идентификаторы

`p1:<hash>:<ordinal>` — идентификатор внутри структурной проекции. Hash вычисляется
из детерминированных узлов/связей, UUID и записей unverified с длинами полей.
Изменённая проекция отвергает чужой ID. Одинаковые проекции имеют одинаковые ID.
Это НЕ snapshot_id и НЕ Git SHA: смена тела BSL без изменения структуры не меняет
эти ID. Никакой гарантии происхождения или идентичности исходных байтов они не дают.
Формат экспериментальный, его не следует сохранять как постоянную внешнюю ссылку.

## Следующий шаг

Методы добавим только после Rust validated lexical facts: точные диапазоны,
дубликаты, отказы и полнота отдельно от семантики. Ссылку на исходник свяжем с
полностью валидированным снимком и его идентичностью; сейчас address — только
точный путь из XML subset, не готовая ссылка на source API. Затем отдельный MCP
адаптер и ограничения сериализованного ответа. Windows/БСП в этом шаге не проверяем.

## Авторские проверки R04-A

В облачном Linux на изолированном Rust 1.85.1 выполнены:

- `cargo test --locked --offline --all-features`: 20 тестов успешно;
- `cargo test --locked --offline`: 1 тест успешно, экспериментальные модули выключены;
- `cargo test --locked --offline --features experimental-tree`: 14 тестов успешно;
- `cargo fmt -- --check` и `git diff --check`: успешно.

Пять новых тестов покрывают пустой корень, строгие лимиты, `usize::MAX` offset,
45 модулей и полный обход страницами по 7, стабильные/чужие ID, кириллические пути,
точную принадлежность модулей, счётчики unverified/unassigned, отказ unsupported,
лимит UTF-8 байтов без обрезания и неизменность projection ID при изменении тела BSL.
Production gate повторно проверен. Независимое ревью требуется отдельно.
