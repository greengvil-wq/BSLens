# ADR-002. Узкий безопасный слой XML 2.21

Статус: согласованный объём R02, не production и не полная эквивалентность Python.
Ветка отделена от принятого R01; его коммит не изменяется.

## Решение до реализации

Используем закреплённые `quick-xml =0.37.5` и `roxmltree =0.20.0`.
Исходники roxmltree проверены: есть запрет DTD и ограничение числа узлов, но нет
ограничения глубины, а значение encoding в декларации не проверяется.
Поэтому потоковый quick-xml выполняет ограниченный предварительный проход: глубина,
число событий, declaration encoding, запрет PI/DTD. Затем roxmltree проверяет
well-formedness, namespace и строит дерево с nodes_limit. Собственный XML-парсер
или загрузка внешних сущностей не реализуются. Цена двух проходов ограничена
лимитами входа; это осознанный выбор безопасности маленького первого этапа.

Возможность `experimental-xml` отдельно включает библиотечный `Xml221Subset`.
Вход — набор уже переданных байтов с точными относительными адресами, не путь к
базе/каталогу и не сеть. Выход — проверенная в рамках этого узкого контракта
структура: Configuration, Catalog, Document, InformationRegister и присутствующие
модули по разрешённым точным путям. Нет MCP, дерева вызовов, полного навигатора
или подключения к experimental SQLite-reader. Выход не содержит Git SHA или
snapshot_id: этот слой не проверяет происхождение Git. Production gate R01 закрыт.

Неподдержанные классы и непустые вложенные ChildObjects отвергаются. Ничего не
маскируется под отсутствие. Неизвестные свойства и дополнительные атрибуты
помечаются как непроверенные; содержимое Properties не получает семантических
гарантий. BSL-модули с недоказанным владельцем перечисляются отдельно.
Полный scoped-профиль Python с исключёнными типами и вспомогательными файлами
не переносится в R02. Непривязанный XML-дескриптор вызывает отказ.

Ограничения входа: адрес до 1024 UTF-8 bytes, 4096 файлов, 32 MiB суммарных bytes, 2 MiB на XML, глубина 64,
20000 событий предварительного прохода и 10000 узлов roxmltree на документ.
Лимиты фиксированы для авторских проверок; достаточность для БСП не заявляется.
DTD, PI, не-UTF-8 encoding, invalid UTF-8, неизвестная версия/namespace,
дубликаты UUID/ссылок и несовпадение case-sensitive имени/пути вызывают отказ
с отдельным кодом. Пробельные отступы, BOM, namespace prefixes допустимы.

Следующий шаг: независимое ревью, более широкий differential corpus, затем
явное расширение subset и проверка связи с полностью валидированным снимком.
Нельзя превращать этот результат в ValidatedSnapshot или считать все guards
перенесёнными. Документация XSD и проверка поведения платформы не заменяются
этими проверками оболочки и идентичности.
