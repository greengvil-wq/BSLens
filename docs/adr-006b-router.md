# R06-B. Read-only tree/source через библиотечный MCP router

Цель: получить дерево и точный исходник одного выбранного Git-коммита через
MCP-запросы, не создавая пока CLI, сетевой сервер или пользовательский интерфейс.
Включение: feature `experimental-router`.

## Как использовать

Вызывающая программа один раз создаёт проверенный `GitStructure`, затем передаёт
его по значению в `CoreSession::new(core)`. После создания заменить core или выбрать
другой репозиторий/коммит через запрос нельзя. `serve` читает NDJSON из переданного
BufRead и пишет в переданный Write; stdin/stdout процессом этот модуль не открывает.
Для проверок есть `handle_body` того же сеанса и того же lifecycle.

После initialize и notifications/initialized вызов tools/list возвращает две
схемы: `tree` и `source`. Там же указаны context (commit/tree), scope и scope_id;
обязательные значения commit/scope_id закреплены в inputSchema через const.

- `tree`: commit, scope_id; необязательно node_id, offset (по умолчанию 0),
  limit (по умолчанию 20, допустимо 1–20). Без node_id раскрывается корень.
- `source`: commit, scope_id, blob_oid, path, start_line, end_line. Объект source
  в деталях метода уже содержит эти аргументы, его можно передать целиком.

Каждый успешный tool result содержит одинаковые context, scope, scope_id и data
в structuredContent и в текстовом JSON. Scope обозначает точные версии ограниченных
XML/structure/lexical/source контрактов, production=false. Scope_id — SHA256
канонической сериализации context+scope. Это не production snapshot_id и не подпись.

## Границы и ошибки

Полный успешный ответ всегда связан с единственным core сеанса. Синтаксически
корректные, но чужие commit/scope_id/node/blob дают отказ, а не переход в другое
состояние. Ни один входной аргумент не используется как путь для чтения с диска.

Неверная форма аргументов, неизвестное имя инструмента, лишние свойства, bool/float
вместо целого, неверные диапазоны и отсутствие обязательных полей — JSON-RPC -32602.
Несовпадение контекста, неизвестный узел, core source range/identity refusal,
лексический отказ или text budget — tool result isError=true. Он содержит только
ошибку, без structuredContent и без выдуманных или частичных данных. Лексический
отказ сохраняет конкретную причину и физическую строку. Ошибки не отражают произвольные
значения запроса; код исходника остаётся данными, не инструкциями для router.

Проверяются существующие library page/source budgets и полный сериализованный
JSON-RPC ответ существующим transport MAX_BODY=65536 байт. Включены обе копии данных,
JSON escaping, id и envelope. Если полный ответ не помещается, transport возвращает
-32001 без result. Обрезания текста или неполной страницы нет.

Адаптер не обращается к сети, не запускает `git fetch`, не пишет в
репозиторий и не включает проверку рабочих снимков. Windows и БСП не
проверялись. Адаптер использует интерфейс `ToolRouter`. Исправление
границы квоты R06-A включено: последний разрешённый ответ записывается
полностью, затем сессия закрывается без дополнительного чтения.
