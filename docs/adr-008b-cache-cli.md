# R08-B. Повторный запуск MCP с явным локальным кешем

Кеш включается только при сборке с `experimental-cache` и передаче `--cache-dir`.
Без этого параметра используется прежнее полное чтение Git без записи кеша.

```sh
cargo build --locked --release --features experimental-router,experimental-cache --bin bslens-mcp
./target/release/bslens-mcp --repo /absolute/repository --commit FULL_SHA --cache-dir /absolute/private-cache
```

Первый запуск при отсутствии файла строит кеш и затем запускает MCP. Повторный
запуск использует кеш, но проверяет реальные Git commit/tree и все соответствия
путей. Поэтому репозиторий всё ещё нужен. Оригинальные blob bodies повторно
не читаются; XML-проверки и построение структуры из кешированных bytes повторяются.

Каталог должен быть absolute, owner-only (0700). Если последнего каталога нет,
он создаётся; его родитель уже должен существовать. Файлы кеша имеют mode 0600.
Не выбирайте каталог, который собираетесь включать в исходный Git-коммит.

Повреждённый, чужой или несовместимый кеш не перестраивается молча. Процесс
завершается с ненулевым кодом и короткой ошибкой в stderr, до протокольного ответа.
Для осознанного перестроения после проверки причины используйте:

```sh
./target/release/bslens-mcp --repo /absolute/repository --commit FULL_SHA --cache-dir /absolute/private-cache --rebuild-cache
```

`--rebuild-cache` без `--cache-dir`, дубликаты параметров и относительный каталог
отвергаются. При небезопасных permissions/symlink перестроение не обходит запрет:
нужно выбрать корректный owner-only каталог. При отсутствии feature параметры
кеша не принимаются. Выбор кеша фиксируется при запуске, из MCP изменить его нельзя.

Все ответы tree/source и scope/context сохраняются. Кеш не является production
SQLite-снимком, не добавляет поддержку Windows/БСП или обновление между коммитами.
Протокол по-прежнему пишет только JSON-RPC в stdout, ошибки запуска идут в stderr.
