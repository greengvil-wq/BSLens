# Приёмка Навигатора на БСП

Принят сценарий «сборка из фиксированного Git-коммита → проверка снимка
без Git → навигация и чтение точного текста через MCP». Это проверка
структуры и исходников, а не корректности компиляции, графа вызовов или
семантики 1С. СППР и ERP УХ этим прогоном не приняты.

## Архив исходников и коммиты репозитория

Все 181 файл принятого архива с SHA-256
`5022f67909a7fd53ee6bbf59e704183c4e9aa76e4d9794d7695488fbaf57bf2d`
совпадают побайтно и по Git-режиму с файлами коммита
`eb7a50e849a2360cb1543df06a4b5bd8272567a3`
(дерево `5c5ad648098ad6959093b063ec23db5869d0366c`).

В дереве коммита 187 файлов. Шесть из них не входят в архив и перенесены
из `main` (`c4791718526c94bf0aa04a09d98cd22b5ce3155b`) без изменений:

- `.gitattributes`
- `.gitignore`
- `.github/workflows/rust-ci.yml`
- `assets/bslens-dark.svg`
- `assets/bslens-icon.svg`
- `assets/bslens-light.svg`

Для сверки из путей архива убирался общий корневой каталог. Для каждого
файла SHA объекта от `git hash-object --no-filters --stdin` (на входе
неизменённые байты из архива) и режим (`100644` или `100755`, по биту
исполнения) сверялись с `git ls-tree -r eb7a50e`. Множество путей дерева
за вычетом шести перечисленных файлов равно множеству путей архива.
Контрольная сумма архива относится к исходному tar.gz, а не к выводу
`git archive`.

Из коммитов после импорта только
`3baf03f8bc4b1fbfcc14ee0f4251cd3931a611fb` меняет Rust-исходники.
`Cargo.toml` и `Cargo.lock` после импорта не менялись. Этот коммит
точно воспроизводит 244 фрагмента вывода rustfmt из Rust 1.85.1 для
47 файлов. Логика не менялась; буквальные потоки токенов не идентичны из-за
перестановок объявлений, добавленных скобок и завершающих запятых.
`492c739` добавляет синтетические материалы в `spikes/`, `94d54aa` и
`9bcad3f` затрагивают только документацию и CI.

В репозитории есть отдельно сохранённые синтетические материалы S1–S2
из PR №8. Реальная выгрузка и SQLite в репозиторий не входят.
