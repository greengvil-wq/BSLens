# R05-B. Метод и точный исходник в GitStructure

Вход остаётся `Manifest` с проверенными Git object identities. GitStructure хранит
копии выбранных BSL blobs, не пути к рабочим файлам. Корень/объекты раскрываются без
лексического сканирования модулей; модуль или метод сканируется по запросу. Кэширования
анализа пока нет. Принятый lexical R04-B перенесён без изменения его реализации.

## Данные

`BoundPage.page.items` теперь может содержать `NodeKind::Method`. На странице модуля
`BoundPage.methods` соответствует этим элементам в том же порядке; при раскрытии
самого метода список содержит одну его запись, детей нет. Запись включает ordinal,
лексическую boundary, blob OID/SHA256, необязательный SourceRef и указатель продолжения.
Одноимённые методы имеют разные ordinal/ID и не объединяются.

ID метода: ID модуля, привязанный к exact commit, плюс `:m:<ordinal>`. При смене коммита
старый ID отвергается, даже если имена/структура сохранились. Чужой commit, неканонический
ordinal и поддельная ссылка на не-модуль не допускаются. Контекст страницы содержит
точные commit/tree; детали метода — OID и SHA256 исходных bytes. Это Git provenance,
но не свидетельство полного production-validation или семантической правильности BSL.

Неподдержанная лексика возвращает `Error::Lexical` с причиной и физической строкой,
без пустого успешного списка и без частичных границ. Владение у unassigned-модулей
и их методов остаётся `unverified`. Coverage сообщает ограниченность lexical subset.

## Source

SourceRef содержит commit, blob OID, точный относительный path и диапазон 1-based
физических строк включительно. Source повторно проверяет commit/OID/path, допустимый
диапазон и лексическую пригодность модуля. Доступен только выбранный BSL blob; DB,
рабочие файлы, сеть и произвольные пути не читаются.

Возвращаются Context, reference, SHA256, текст, start/end bytes и координаты каждой
физической строки. Байтовый конец исключён. Физические строки включают отступы,
комментарии и CRLF; boundary метода по-прежнему задаёт более узкий token span.
Source не обещает ровно тело метода и может вернуть другой разрешённый диапазон
того же проверенного модуля по явному SourceRef. Ошибочная лексика блокирует source
в этом узком маршруте, даже если provenance bytes известен.

Не более 100 строк. Сумма переменных строковых полей ответа source, включая текст,
контекст и reference, не превышает 16384 UTF-8 bytes. Страница ограничена 20 элементами
и тем же бюджетом переменных строковых полей, включая детали методов и source hints.
Числовые поля имеют ограниченное количество. Это не лимит JSON/MCP-конверта: он будет
добавлен при реализации транспорта. Превышение — явный TextBudget, без clipping.

Source hint покрывает максимально допустимый начальный диапазон метода до 100 строк
и байтового бюджета. `source_next_line` показывает продолжение. Если первая физическая
строка слишком велика, hint отсутствует и `source_unavailable` объясняет причину.

## Авторские проверки

Все данные синтетические, только cloud Linux, Rust 1.85.1, locked/offline:

- all-features: 46 тестов успешно;
- experimental-pipeline: 40 тестов успешно;
- default: 1 тест успешно; production gate закрыт;
- fmt/diff checks успешно.

Сквозные проверки: Git commit → XML → модуль → два одноимённых русских метода →
физический source; BOM/CRLF/emoji, dirty worktree не подменяет bytes; новый commit
сдвигает строки и отвергает старые ID/SourceRef; blob OID подменить нельзя;
неподтверждённый владелец остаётся таковым. Embedded NUL и conditional дают явный
лексический отказ. Проверены поддельные ordinal, offset за концом, диапазоны,
source на 100/101 строку, отсутствие hint для сверхдлинной первой строки и
точная multibyte граница бюджета: равенство проходит, плюс один байт отвергается.

Независимое ревью exact candidate необходимо отдельно. Windows/БСП, MCP, полноценная
семантика, кэширование и performance большого корпуса в этот этап не входят.
