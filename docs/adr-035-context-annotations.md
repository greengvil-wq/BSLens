# ADR-035: отдельный лексический guard контекстных аннотаций

Основа `ab97b77597841aa369695caa2f6affa809723cca`. Новый явный CLI
`build-context`, профиль `linux-v5-context1-xml221-r09`, lexical_version
`r09-context-ru-v1`. Прежние команды и профили сохраняют `r09-regions` guard и отказывают
на аннотациях. DDL меняет только discriminator профиля, таблицы не меняются.

## Узкий синтаксический контракт

Разрешены только точные строки `&НаКлиенте`, `&НаСервере`,
`&НаСервереБезКонтекста` с необязательными пробелами/табуляцией по краям.
Регистр точный; английские и смешанные варианты, аргументы, суффиксы и комментарий
на этой строке не принимаются. Одна аннотация на уровне модуля, непосредственно
следующая физическая строка — допустимая прежним guard декларация процедуры или
функции без аргументов. Прежняя поддержка Export/Экспорт сохраняется.

Пустая строка, отдельный комментарий, вторая аннотация (включая дубль),
посторонний токен, граница области или директива между аннотацией и декларацией
дают отказ. Аннотации внутри тела и inline также отвергаются. Незавершённая
аннотация в конце файла не теряется. Обычная сбалансированная область вокруг
метода допустима; pending-аннотация не пересекает её границу. `#If`, аргументы и
другие неподдержанные заголовки остаются вне этого среза. Это не анализ корректности
компиляторного контекста, обработчиков или семантики вызовов.

Любая неподдержанная конструкция делает **весь** модуль `unparsed`, с нулём
выведенных методов, даже если перед ней был допустимый метод. Это не доказательство
отсутствия методов. Accepted с нулём методов остаётся отдельным состоянием.

## Байты, identity и наследование

Диапазон метода по-прежнему начинается с ключевого слова декларации и заканчивается
концом метода. Предшествующая аннотация не включается в этот диапазон, но полностью
сохраняется в sources и доступна отдельным диапазоном. BOM, CRLF и последняя строка
без LF не нормализуются. Номера строк остаются физическими, byte offsets прежними.

Один общий producer выбирает guard по новому профилю при build и offline verify.
В нормализованных build_parameters зафиксированы lexical_guard, allowlist,
точное сравнение, физическая смежность и правило диапазона. Они входят в identity;
подмена профиля или lexical_version не превращает старый снимок в новый.

Профиль наследует весь root-sidecar1: источники и selector, действительных owners,
optional формы, bounded diagnostic rows/count/digest, facts digest, XML provenance,
root sidecar summary и исключение HTML этих семейств. Лимиты файла/ввода/SQLite,
метаданных и MCP не повышаются. Лексические пределы остаются 1 MiB, 65536 строк,
100000 токенов, 64 уровня областей. Строка аннотации учитывается как два токена.
MCP явно сообщает `lexical_guard=r09-context-ru-v1` и
`compiler_context=not_semantically_verified`; lookup не выбирает молча дубль.

## Воспроизводимый запуск

Использовать команды и все 21 аргумент из [ADR-034](adr-034-root-sidecars.md),
заменив только `build-root-sidecars` на `build-context`. Offline verify и stdio MCP
остаются прежними, включая явные BIN/diagnostics quotas, trusted staging и
независимый expected SHA. Git не нужен после сборки.

```sh
cargo +1.85.1 test --locked --features experimental-snapshot-mcp context_ -- --nocapture
cargo +1.85.1 test --locked --all-features
cargo +1.85.1 test --locked --features experimental-router
cargo +1.85.1 test --locked
cargo +1.85.1 fmt --check
git diff --check
```

Синтетический integration test вызывает настоящий build, сравнивает старый профиль,
повторяет сборку для детерминизма, удаляет только собственный временный Git и
запускает verify/stdio с пустым PATH. Проверяет все три аннотации, BOM/CRLF,
точные байты всех модулей и метода, неоднозначность имени, десять отказных модулей,
нулевые методы у unparsed, сохранённые diagnostics/sidecars и подмену факта с
согласованными digest: формальный open проходит, offline verify отвергает.

Переданная статистика БСП — основание выбора среза, а не измерение этого кандидата.
Новый процент accepted неизвестен до отдельного локального повтора на NucBox.
Полная БСП не принята: ограничения заголовков, директив и иных конструкций остаются.
Реальные данные, main и GitHub здесь не используются.
