# ADR-007. Один ограниченный процесс чтения Git-объектов

## Решение

Один вызов `Manifest::read` использует один `git cat-file --batch` вместо
нового процесса на каждый объект. Процесс не сохраняется между открытиями
манифеста или MCP-сессиями. Публичные API, формат дерева, исходника и coverage
не меняются. Новых зависимостей Cargo или среды выполнения нет.
Только тесты с имитацией дочернего процесса требуют `/usr/bin/python3`;
для запуска BSLens Python не нужен.

Доверенный Linux backend по-прежнему запускает фиксированный `/usr/bin/git`
с очищенным окружением и отдельным временным bare-каталогом. Рабочая копия,
настройки и hooks входного репозитория не используются; replace, lazy fetch и
alternates остаются запрещены. Windows требует отдельного backend и проверки.

## Чтение и отказ

Поток обрабатывает один запрос за раз. Один рабочий поток владеет stdin/stdout,
координатор владеет дочерним процессом. Два канала ёмкостью один ограничивают
число ожидающих запросов и ответов. Общий абсолютный deadline манифеста покрывает
запись запроса, flush, чтение заголовка, тела и завершение процесса.

Заголовок ограничен 128 байтами, включая LF. До выделения памяти под тело
проверяются точный OID, ожидаемый тип, каноническое десятичное значение длины и
оставшийся бюджет. Затем читаются ровно тело и один LF. Буфер между запросами
сохраняется. Хеш Git каждого commit/tree/blob независимо пересчитывается,
как раньше. Все прежние лимиты числа файлов, объектов, байтов и глубины сохранены.

Ошибка не допускает синхронизации заново или повторного использования потока.
Координатор закрывает канал запросов, завершает и забирает статус дочернего
процесса, затем соединяет рабочий поток. Ранний отказ при обходе или проверке
хеша проходит тем же путём через Drop. Отдельный успешный `finish` после обхода
закрывает stdin, требует EOF без лишних байтов и успешный exit status до возврата
манифеста. EOF без успешного завершения не считается успехом.

Принудительная очистка использует системные kill/wait и предшествует join.
Она рассчитана на фиксированный Git, который не создаёт помощников, удерживающих
pipes. Это не исполнитель произвольных программ и не гарантия времени ответа ОС
при неустранимом зависании ядра. Изоляция репозитория и платформенные ограничения
не расширяются ради ускорения.

## Проверка

Синтетические тесты проверяют два запроса в один процесс, границы заголовка,
неверные OID/тип/длину, лишний или отсутствующий LF, усечённое тело, EOF,
неуспешный exit, timeout, очистку и запрет повторного использования после ошибки.
Существующие проверки Git, XML, дерева, source и MCP должны проходить без изменения
ожидаемых результатов. Сравнение скорости проводится отдельно на одинаковом
полном SHA и одинаковых ответах. Оно не доказывает поддержку БСП или Windows.

Production-проверка SQLite-снимка по-прежнему закрыта.
