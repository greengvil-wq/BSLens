# ADR-021: точный фильтр видимого имени в MCP

Основа 2f846b7518bc9c94a7dc7501256576c0b90d076b. Это расширение необязательных
аргументов `tree`, без новых видов, профилей SQLite, таблиц, индексов, парсеров или
изменения snapshot_id/facts_sha256. Старые запросы без фильтра сохраняют поведение,
в том числе полный отказ ветки при превышении 128 узлов или бюджета байтов.
R09-режим MCP без snapshot не меняется.

## Запрос и сравнение

`tree` принимает необязательный `name_exact` только для:

- `level=kind`: видимое имя объекта внутри заданных kind и parent_id;
- `level=module`: видимое имя метода внутри заданного module_path.

Имя — непустая строка максимум 1024 UTF-8 байта. Сравнение SQLite COLLATE BINARY:
точное, с учётом регистра, без Unicode-нормализации, обрезки пробелов, wildcard,
подстроки или неявного выбора первого совпадения. `%` и `_` — обычные символы.
Имя сравнивается с тем же полем name, которое показывает нефильтрованное дерево.

**Особенность существующего R09:** имена методов уже сохранены и видимы в нижнем
регистре. Метод из исходника `Процедура Цель()` виден как `цель`; name_exact="цель"
совпадёт, name_exact="Цель" — нет. Сам фильтр ничего не переводит в нижний регистр.
Имена объектов сохраняют регистр XML. Исходные байты BSL не изменяются.

`name_exact` на configuration/object/unconfirmed/inline/companions, null, число,
пустая или слишком длинная строка → JSON-RPC -32602. Инструмент `tools/list`
объявляет новый параметр. Остальные ограничения формы аргументов сохранены.

## Поиск без заранее известных ID и путей

1. Вызвать `tree` без arguments; выбрать в ответе вид по name, например CommonModule.
2. Скопировать его children и добавить `name_exact` с известным именем объекта.
3. Использовать children найденного объекта. Выбрать его модуль из ответа и
   скопировать children модуля, добавив `name_exact` с видимым именем метода.
4. Передать source найденного метода инструменту source; декодировать utf-8 или
   base64 согласно encoding и сверить точные байты.

ID, пути и диапазоны берутся из ответов, а не угадываются. Если у объекта несколько
модулей, клиент выбирает нужный модуль явно. Это поиск внутри одной ветки, не
глобальный поиск и не семантическое разрешение ссылки. Формы/объекты с одинаковыми
именами у разных родителей не смешиваются.

## Ответ и полнота

Для фильтрованного запроса branch содержит name_exact,
name_comparison=`utf8_binary_case_sensitive_no_normalization` и match_status:

| Статус | Значение |
|---|---|
| matched | одно сохранённое совпадение |
| no_match | совпадений нет в выбранной ветке; для методов только при accepted |
| ambiguous | несколько совпадений, все возвращены в прежнем порядке |
| unparsed | модуль не разобран; отсутствие метода неизвестно, reason сохранён |

При фильтре complete_branch=false: ответ не изображает полную исходную ветку.
complete_matches=true только для полного результата сравнения; у unparsed — false.
Accepted с нулём методов отличается от unparsed. Отсутствующий родитель/модуль
остаётся прежним отказом not_found, а не успешным no_match.

Если совпадений больше max_nodes или они не помещаются в бюджет текста/полный
JSON-RPC, возвращается прежний budget_exceeded без частичного payload. Дубли
не сводятся к первому результату. Методы с одинаковым именем имеют разные ключи
и source-диапазоны; в пределах бюджета возвращаются все с ambiguous.

## Ограничения реализации

Фильтр передаётся параметром SQL и применяется до preflight числа строк и длин,
затем до материализации отсортированного ответа. Большая исходная ветка сама по
себе не вызывает отказ, если совпадения укладываются в бюджеты. Сохраняются 128
узлов по умолчанию/максимум, доверенный бюджет текста reader и 65536 bytes на весь
сериализованный JSON-RPC. Полная ветка не загружается в Rust для поиска.
Reader использует прежнюю immutable private copy; нет повторного открытия снимка,
Git или BSL-разбора на инструмент. Время полного SQL-сканирования большого модуля
не превращается в обещание постоянной стоимости поиска; отдельный индекс по
имени метода в этом шаге не добавлен. Произвольный вредоносный SQLite не входит
в гарантию безопасности reader.

## Проверки

```sh
cargo +1.85.1 test --locked --all-features
cargo +1.85.1 test --locked --features experimental-router
cargo +1.85.1 test --locked
cargo +1.85.1 fmt --check
git diff --check
cargo +1.85.1 test --locked --features experimental-snapshot-mcp --test mcp_snapshot exact_name_cli
```

Запуски с общим target выполнять последовательно. Сквозной тест создаёт 804
CommonModule и 261 метод в целевом модуле (129 отдельных, два duplicate, 129 many,
одна цель в конце). Реальный build-journals → удаление только тестового Git →
offline verify → stdio initialize/tools/list/tree/source с пустым PATH.
Нефильтрованные ветки отвергаются; обе цели найдены без заранее введённых ID/путей,
исходник целевого метода возвращён byte-exact с CRLF и последней строкой без LF.
Проверены no_match, регистр, буквальные wildcard, дубли, 129 совпадений, max_nodes=1,
unparsed, accepted без методов, неверные аргументы и отдельный byte-budget reader.
Другие тесты сохраняют проверку лимита полного сериализованного JSON-RPC.

Синтетика не является приёмкой реальной БСП. Рабочие данные не читались, NucBox не
использовался. Для локальной диагностики снимка действуют прежние команды
[nucbox-journal-diagnostic.md](nucbox-journal-diagnostic.md); добавляется только
навигация по имени, описанная выше. Остальные структурные блокеры БСП не устраняются.
