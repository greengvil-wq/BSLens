# Linux v5: S1–S2

Контракт и ограничения: [ADR-010 S1–S2](../../docs/adr-010-s1-s2.md).
Весь материал фикстуры придуман для теста; реальных исходников 1С нет.

Запуск из корня проекта, без сторонних Python-пакетов:

```sh
python3 -m unittest discover -s spikes/linux-v5 -v
```

Нужен Python 3.11+ с `sqlite3.blobopen`, SQLite 3.37+ с `json_valid`.
`fixture.py` создаёт только известный набор литералов в переданном тестовом
соединении, не читает каталог проекта, Git или произвольную выгрузку. Ожидаемые
объекты/владельцы/метод заданы вручную: XML/BSL-парсеры этим тестом не проверяются.
Тесты используют память и временный каталог, SQLite-файлы не коммитятся.

Фикстура: конфигурация SyntheticV5; справочники Items и Empty (без модулей);
документ Order; принятая экспортная процедура; неразобранный модуль RegionHeader
с UTF-8 BOM, CRLF и последней строкой без LF; модуль без подтверждённого владельца.
Все XML и BSL сохраняются точными BLOB. Повторяемость проверяется логическим SQL
дампом, не обещанием одинакового физического расположения страниц SQLite.

Проверено в облачном Linux 6.18.57, Python 3.12.14, SQLite 3.53.1: 11 тестов.
Проверки: версии/профиль, состав таблиц, FK и CHECK, режим и BLOB, статусы и причины,
ветки дерева/порядок/пустой объект, полнота строк, хеши источников, каждый диапазон
неразобранного модуля побайтно, краевые случаи строк, повторяемость и повторное
открытие самостоятельного файла без sidecar-файлов.

Rust-код и зависимости не менялись. `cargo +1.85.1 test --locked` и
`cargo +1.85.1 test --locked --all-features` не выполнены: `cargo`, `rustc`,
`rustup` отсутствуют в PATH. Установка ПО и изменение настроек не выполнялись.
Python/SQLite-тесты не заменяют Rust-регрессию; её нужно выполнить в оснащённой среде.
